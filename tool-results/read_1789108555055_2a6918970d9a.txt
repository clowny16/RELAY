     1→Build a Production-Ready Browser-Only File Conversion SaaS
     2→Build a modern SaaS web application for client-side file conversion. The core product is a privacy-first “Convert Anything” file conversion platform where files are processed entirely inside the user's browser whenever technically possible.
     3→
     4→The application must NOT upload user files to our servers for conversion.
     5→
     6→The product should feel polished, fast, trustworthy, modern, and production-ready — not like a basic file-upload utility.
     7→
     8→
     9→1. Core Product Concept
    10→Create a SaaS platform where a user can:
    11→
    12→Select or drag-and-drop one or multiple files.
    13→Automatically detect each file's format.
    14→Select a compatible output format.
    15→Convert the file directly inside the browser.
    16→See real-time conversion progress.
    17→Preview the result when possible.
    18→Download the converted file.
    19→Download multiple converted files as a ZIP.
    20→Convert multiple files in batch.
    21→Perform archive operations such as ZIP/TAR/7Z conversions and extraction.
    22→Never send the user's actual file contents to a conversion backend.
    23→The main selling point is:
    24→
    25→Your files stay on your device.
    26→Use privacy as a major part of the product experience.
    27→
    28→
    29→2. Important Architecture Requirement
    30→The application must be frontend-first / browser-only for file processing.
    31→
    32→Do NOT create a backend API that receives uploaded files for conversion.
    33→
    34→All supported conversions should run locally using:
    35→
    36→JavaScript
    37→Web APIs
    38→Web Workers
    39→WebAssembly
    40→Client-side libraries
    41→Browser-native APIs where appropriate
    42→Use Web Workers for CPU-heavy operations so that the UI remains responsive.
    43→
    44→Large files must not block the main browser thread.
    45→
    46→If a conversion cannot reliably be performed locally, clearly mark it as:
    47→
    48→“Not supported in browser”
    49→rather than secretly uploading the file to a server.
    50→
    51→
    52→
    53→The architecture should separate:
    54→
    55→SaaS Account Data
    56→↓
    57→Authentication / Billing
    58→
    59→User File
    60→↓
    61→Browser
    62→↓
    63→Local Conversion Engine
    64→↓
    65→Downloaded Result
    66→
    67→Never mix the two.
    68→
